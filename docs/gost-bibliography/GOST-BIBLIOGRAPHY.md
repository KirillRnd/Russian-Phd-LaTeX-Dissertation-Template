# Библиография диссертации: единая нормативная выжимка

Обновлено: 29 августа 2026 года.

Этот файл — нормализованный рабочий результат однократного разбора локальных
ГОСТов. Для настройки `.bib` и проверки результата обращаться нужно к этому
Markdown, а не повторно извлекать текст из PDF. Формулировки сокращены и
сведены к правилам, применимым к диссертации; при споре приоритет имеет текст
соответствующего стандарта.

## 2. Решение для этой диссертации

1. Список литературы формируется по ГОСТ Р 7.0.100–2018.
2. Электронные документы дополнительно проверяются по ГОСТ Р 7.0.108–2022.
3. Внутритекстовые числовые ссылки обслуживает `gost-numeric`; правила
   ГОСТ Р 7.0.5–2008 не используются как повод возвращать старое описание
   электронного ресурса.
4. Старые общие обозначения `[Текст]` и `[Электронный ресурс]` не выводятся.
   Вид электронного документа передаётся конкретным обозначением ресурса,
   контейнером, URL, датой обращения и DOI.
5. DOI, ISBN и ISSN не удаляются. DOI предпочтительнее нестабильного URL, но
   наличие DOI не запрещает привести URL официальной страницы, когда это
   полезно для идентификации сетевой версии.
6. Язык библиографической записи хранится в `langid`, а не в печатаемом поле
   `language`. Благодаря этому русская запись получает русские сокращения, а
   английская — английские.

## 3. ГОСТ Р 7.0.11–2011: список литературы диссертации

По разделу 5.6:

- список включает документы, действительно использованные при работе;
- список помещают после основного текста (и словаря терминов, если он есть);
- допустима алфавитная, систематическая или хронологическая группировка;
- при алфавитной группировке записи располагают по фамилиям авторов либо по
  первым словам заглавий; однофамильцев — по инициалам;
- выбранный способ должен быть единообразным.

В проекте используется порядок первого упоминания (`sorting=none`) и единая
сквозная нумерация.

## 4. ГОСТ Р 7.0.100–2018: состав полного описания

### 4.1. Общие положения

Стандарт различает обязательные, условно-обязательные и факультативные
элементы. Для одного информационного массива набор факультативных элементов
должен быть постоянным. Области описания и их элементы приводятся в
установленной последовательности. В конце записи ставится точка.

Для проекта принят устойчивый набор:

- автор или иной заголовок записи;
- основное заглавие;
- сведения, относящиеся к заглавию, если они нужны для идентификации;
- сведения об ответственности;
- сведения об издании;
- место, издатель, дата;
- сведения о серии/журнале/сборнике;
- том, выпуск, номер, страницы или общий объём;
- стандартные идентификаторы;
- для сетевого документа — URL и дата обращения.

### 4.2. Автор и заголовок записи

- Личное имя хранится структурированно: `Фамилия, Имя/инициалы`.
- Соавторы разделяются оператором BibLaTeX `and`, а не запятыми.
- При четырёх и более авторах стиль может формировать запись под заглавием и
  переносить имена в сведения об ответственности (`movenames=true`).
- Коллективный автор не разбивается на имя и фамилию и заключается в
  дополнительную пару фигурных скобок.
- Не следует подменять отсутствующего автора редактором или организацией.

### 4.3. Заглавие и сведения об ответственности

- `title` содержит только заглавие описываемого документа.
- Переводчики, редакторы, составители, авторы предисловия и формулы вида
  «под редакцией» относятся к зоне ответственности, а не к `note`.
- Структурируемые лица заносятся в `editor`, `translator` и другие именные
  поля. Неструктурируемая дословная формулировка допускается в `credits`
  пакета `biblatex-gost`.
- `note` оставляют для настоящего примечания о документе, а не для данных,
  которые имеют собственное поле.

### 4.4. Издание, выпуск и страницы

- Повторность или редакция издания — `edition`.
- Для журнальной статьи название журнала — `journaltitle`, год — `date`, том —
  `volume`, номер/выпуск — `number`, диапазон страниц — `pages`.
- Для главы или статьи в сборнике название части — `title`, название сборника
  — `booktitle`, страницы части — `pages`.
- `volume` не должен одновременно содержать номер выпуска: `Т. 12, № 3`
  раскладывается в `volume={12}` и `number={3}`.
- Диапазон страниц в `.bib` записывается `31--40`; стиль сам выводит нужное
  тире и локализованное обозначение страниц.
- Общий объём книги — `pagetotal`, а не `pages`.

### 4.5. Место, издатель и дата

- Полные формы места издания предпочтительны: `Москва`, `Санкт-Петербург`,
  `London`, `Paris`; старые сокращения `М.` и `СПб.` не генерируются заново.
- Издатель хранится без вводных слов, если они не являются частью официального
  наименования.
- `date` используется вместо разрозненных `year`/`month`, когда нужна полная
  или интервальная дата.
- Неизвестные сведения не выдумываются. Для отсутствующей даты используется
  документированное обозначение только после ручной проверки источника.

### 4.6. Идентификаторы

- `doi` хранит только DOI, например `10.1234/example.5`, без префикса
  `https://doi.org/`.
- `isbn` и `issn` сохраняются, если известны и относятся к описываемому
  изданию.
- Идентификатор не заменяет основные выходные сведения.

## 5. ГОСТ Р 7.0.108–2022: электронные документы

### 5.1. Минимальный состав

Для сетевого документа необходимо идентифицировать сам документ, а не только
главную страницу сайта. Рабочая запись содержит:

- автора или организацию, если они указаны;
- заглавие документа/страницы;
- название сайта, журнала, репозитория или иной платформы;
- дату публикации/обновления, если она известна;
- `URL:` и точный адрес;
- дату обращения в формате `ДД.ММ.ГГГГ` в печатной форме
  (`YYYY-MM-DD` в `.bib`);
- режим доступа, если доступ ограничен;
- DOI или другой постоянный идентификатор, если он присвоен.

Сведения, взятые вне самого документа, в ссылке приводятся без квадратных
скобок. Поэтому старое `[Электронный ресурс]` не является универсальным
признаком современной ссылки.

### 5.2. Дата обращения и дата публикации

- Дата обращения обязательна для изменяемого сетевого ресурса и показывает,
  когда адрес был проверен.
- Дату нельзя восстанавливать из года публикации или придумывать задним
  числом.
- Если стандарт для конкретного электронного журнала требует дату публикации,
  она приводится как дата публикации; это не разрешает терять дату доступа к
  динамической странице в рабочей базе.

### 5.3. URL и DOI

- URL должен вести на конкретную публикацию, словарную статью, набор данных или
  версию программы; корень сайта допустим только для описания сайта целиком.
- Лишние `#`, `URL:` внутри поля, типографские тире и конечная пунктуация в URL
  являются ошибками данных.
- DOI нормализуется отдельно. Строка `https://doi.org/10...` преобразуется в
  `doi={10...}`.
- Для статьи с DOI предпочтительна официальная страница издателя или журнала,
  а не агрегатор и не случайная копия PDF.

### 5.4. Отдельные виды электронных документов

- Статья электронного журнала остаётся `@article`, а не `@online`.
- Глава в электронной книге остаётся `@incollection`.
- Словарная или энциклопедическая статья без самостоятельных выходных данных
  обычно описывается как `@online` с организацией/сайтом.
- Программное обеспечение описывается как `@software` с автором/разработчиком,
  названием, версией, организацией/репозиторием, датой, URL и датой обращения.
- Набор данных — `@dataset` с версией, издателем/репозиторием и постоянным
  идентификатором.
- Сообщение или комментарий в социальной сети описывается как самостоятельный
  документ с автором, датой, платформой и точным URL.
- Для аудио- и видеодокументов указывается вид документа и длительность, если
  она является идентифицирующим элементом.

## 6. Русские и иностранные записи

### 6.1. Общее правило

Сведения воспроизводятся на языке источника. Иностранное издание не переводят
на русский только ради списка. Транслитерация допустима, когда она задана
издателем или правилами конкретного совета, но не должна смешиваться с
оригиналом внутри одного поля.

### 6.2. `langid`

| Язык записи | Значение |
|---|---|
| русский | `langid={russian}` |
| английский | `langid={english}` |
| каталонский | `langid={catalan}` |
| испанский | `langid={spanish}` |
| французский | `langid={french}` |
| немецкий | `langid={german}` |
| итальянский | `langid={italian}` |
| португальский | `langid={portuguese}` |

`langid` управляет строками и переносами, но сам не печатается как примечание
о языке. Реальное поле `language` заполняется только тогда, когда язык является
необходимой характеристикой документа.

### 6.3. Примеры данных

Русская статья:

```bibtex
@article{example-ru,
  author       = {Иванов, И. И.},
  title        = {Название статьи},
  journaltitle = {Название журнала},
  date         = {2025},
  volume       = {12},
  number       = {3},
  pages        = {15--29},
  doi          = {10.0000/example},
  langid       = {russian},
}
```

Английская статья:

```bibtex
@article{example-en,
  author       = {Smith, John and Brown, Alice},
  title        = {Article Title},
  journaltitle = {Journal Title},
  date         = {2025},
  volume       = {12},
  number       = {3},
  pages        = {15--29},
  doi          = {10.0000/example},
  langid       = {english},
}
```

Электронная словарная статья:

```bibtex
@online{example-dictionary,
  title        = {Название словарной статьи},
  organization = {Название словаря или организации},
  url          = {https://example.org/exact-entry},
  urldate      = {2026-08-29},
  langid       = {russian},
}
```

## 7. Что изменилось по сравнению со старой практикой

| Старая практика | Принято сейчас |
|---|---|
| Ориентация на ГОСТ 7.1–2003 | ГОСТ Р 7.0.100–2018 |
| Заголовок по ГОСТ 7.80–2000 | ГОСТ Р 7.0.80–2023 |
| Универсальное `[Электронный ресурс]` | конкретный вид ресурса + URL + дата обращения |
| DOI/ISBN/ISSN часто скрывались | идентификаторы сохраняются и выводятся |
| Все иностранные записи фактически считались английскими | явный `langid` каждого языка |
| Переводчик/редактор попадал в `note` | именные поля или `credits` |
| URL мог вести на главную страницу | точный URL объекта |
| В `volume` хранились том и номер вместе | отдельные `volume` и `number` |

## 8. Матрица обязательной проверки `.bib`

### Для каждой записи

- уникальный ключ;
- корректный тип записи;
- заглавие без выходных данных;
- авторы и редакторы разделены `and`;
- год/дата не взяты из даты обращения;
- `langid` соответствует языку записи;
- диапазоны страниц записаны через `--`;
- зона ответственности не спрятана в `note`;
- DOI не содержит URL-префикс;
- том и номер разделены.

### Дополнительно для электронного ресурса

- точный URL;
- `urldate`;
- DOI/версия/дата публикации, если существуют;
- организация или контейнер;
- нет старой пометы `[Электронный ресурс]`;
- запись не ошибочно превращена в `@online`, если это статья или глава.

## 9. Локальная политика проекта

- Единственный редактируемый источник — `.bib`; DOCX-импорт удалён.
- Печатный результат проверяется через отдельную HTML-сборку библиографии.
- `annotation` не печатается и служит только историческому аудиту.
- Сомнительные сведения не исправляются эвристически без первичного или
  издательского источника.
- После массовой правки обязательны Biber-валидация и просмотр HTML.
